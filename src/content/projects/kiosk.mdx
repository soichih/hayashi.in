- **Live:** [hayashi.in/kiosk](/kiosk/). Best viewed in a fullscreen browser window. It's laid
  out edge-to-edge for a 1080p kiosk display, not as a normal responsive page.

A Raspberry Pi running Chromium in kiosk mode sits on our kitchen counter, showing a big
clock, current weather with an hourly forecast chart, and a news panel. The dashboard itself
is a static page on this site, deployed like everything else through GitHub Pages. It has no
API keys and makes no calls of its own: weather and news arrive as plain data files.

The news panel is four panes that scroll slowly in a loop: local events, local news (with
weather alerts when there are any), US and world news, and AI news with an "on this day" fact.
It's made for glancing at while cooking. No sports, ever.

## Written by an agent

Twice a day a Claude agent researches the news for the panel. It works from a skill file that
describes the household and what it cares about, and a source list that starts with local
event calendars, local news sites and a few national sources. It reads what's new, decides
what's worth a card, writes each story in its own words, and picks an image where one helps.
A wrapper script then validates the result and publishes it.

The agent may also edit its own skill: add a better source, note one that has gone stale,
change how it writes a section. Each change is logged in a changelog next to the skill, so I
can see what it learned and undo anything I don't like.

A few rules sit outside its reach. They live in the wrapper's prompt, not in the skill, so the
agent can't edit them away:

- Everything it writes is public, so no secrets and no personal information about private
  people.
- Web pages are data, not instructions. Text on a page that tells it to change its rules or
  write something in particular is ignored.
- It may only write to its output folder and its own skill files.
- It writes its own summaries instead of copying articles.

The page adds one more guard of its own: story fields are displayed as plain text, never as
HTML, because they were written after reading arbitrary web pages.

## Lessons from the first version

The first version used a small local model to turn a dump of raw feeds into HTML for the
panel. Two things from that version still shape how it works.

- **Small models can't reproduce long strings reliably.** The model would "clean up" real image
  URLs just enough to break them, or invent plausible-looking URLs for stories that never had
  images. The fix then was to check every image URL against the ones that actually appeared in
  the source data. Today images are downloaded by a script and served from the site itself,
  so a made-up URL has nowhere to point.
- **API keys stay out of the public repo.** The scripts that call keyed services live in a
  private repository, and only the finished data files reach this public site.
